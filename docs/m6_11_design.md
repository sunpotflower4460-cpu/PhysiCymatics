# M6-11 設計: 運動方程式からの加速度評価を砂の計算へ安全に接続する

## 背景

M6-10で、現行のHermite 2階微分による板加速度には最大1.44e3 m/s²の
表現誤差（全モード励振・152Hz区間条件、解析解基準）があり、
補間した変位・速度をモード方程式へ戻す方式（候補B）で約1/19に
なることを確認した。本段階では候補Bを研究用切替として実装し、
離脱判定と休止保証まで含めて成立させる。既定は従来方式のまま
（ビット一致を維持）。

## 候補Bの整合性問題（本質）

候補Bの加速度は、Hermite変位の厳密な2階微分ではない。測定すると:

- 現行（A）: 運動学的に整合（加速度＝変位の2階微分そのもの）。
  しかし運動方程式の残差が大きい（＝その加速度は方程式の解の
  加速度から遠い）。区間境界で加速度が跳ぶ。
- 候補B: 運動方程式の残差は定義により0。加速度は境界で連続。
  しかし「速度の微分として得た加速度」とは一致しない
  （不整合の大きさはAの残差と等しい）。
- 候補C（五次Hermite）: 端点の変位・速度・加速度（方程式から）で
  1本の多項式を作るため、運動学的に整合し、加速度も連続で、
  残差も小さい。ただし変位そのものの表現が変わるため、高さに
  依存する既存の証明（高さ上限・区間範囲・非接触証明）を
  すべて作り直す必要がある。

候補Bで物理的に意味を持つのは、「接触・離脱の判定に使う加速度は、
板の運動方程式に従う値であるべき」という側である。砂の位置を
決める高さ・速度は従来どおりであり、候補Bが変えるのは加速度の
評価だけである。この非対称性は明示的に記録し、候補Bを
「物理的に完成した方式」とは呼ばない。長期の正解候補はCだが、
本段階では板単独の評価に留める。

## 実装（研究用切替・既定OFF）

TypeScript / Python 両方に同じ意味の切替を実装した。

- `TransientPlate.accelMode: 'hermite' | 'ode'`（TS）、
  `TransientPlate.accel_mode`（Python）。既定は `'hermite'`。
- `'ode'` のとき、モード加速度は
  `Φ_drive·F(τ)/M − 2ζω·q'(τ) − ω²·q(τ)`
  （q, q' は従来のHermite補間値、F は score の駆動力）で評価する。
  高さ・速度の評価は1ビットも変わらない。
- UI・Worker には露出しない。研究コードとテストからのみ使う。

### 離脱判定の再設計

現行の離脱時刻は「加速度が区間内で線形」という前提の厳密解である。
ODE加速度は区間内で線形でない（駆動力の正弦波を含む）ため、
ODEモードでは専用経路に切り替える:

- 区間を8等分して加速度＋重力を走査し、最初に負になる小区間を
  40回の二分探索で絞り込む。
- 小区間の中で開いて閉じる根の対は見逃し得る（接触サンプリングと
  同じ種類の限界）。厳密とは呼ばない。見逃し率は実験で測った
  （`docs/m6_11_results.md`）。

### 休止保証の再導出

着座休止は「未来区間の加速度の下限が重力に勝つ」ことの証明に
依存する。ODEモードでは区間の加速度範囲を、Hermite変位・速度の
厳密な範囲と駆動力の上限による区間演算で再導出した:

`qdd ∈ [−|Φ_drive/M|·Fmax − 2ζω·qdmax − ω²·qmax,  +|Φ_drive/M|·Fmax − 2ζω·qdmin − ω²·qmin]`

（Fmax は区間と重なる score イベントの最大力。包絡と正弦は
[−1,1] 内にあることを使う。丸め分の微小拡張つき。）

高さだけに依存する証明（飛行休止の高さ上限、非接触証明、
ライブ自由度マスク、領域共有の高さ範囲）は、変位の表現が
不変なためそのまま成立する。領域共通の着座下限は加速度範囲を
経由するため、上記の新しい範囲で自動的に置き換わる。

## advanceTo の呼び出し分割について

原因は特定済み: `advanceTo(T)` は残り時間でステップを短縮するため、
呼び出し境界が板の区間分割を変える。短縮ステップは休止の全起床も
引き起こす。対策の設計:

- 短期（現状の運用）: 本番Worker は公称ステップ `step()` のみを
  使っており、区間格子は実質的に正準化されている。任意時刻への
  `advanceTo` を使う呼び出し側は、公称刻みの倍数の時刻を目標に
  することで再現性を保てる（実測で確認）。
- 長期: 正準ステップ格子を内部に固定し、任意時刻の状態は
  区間内の読み取り専用評価で返す方式。本段階では実装しない
  （粒子ごとのイベント処理を区間途中で止めて再開する再設計が
  必要なため）。一時停止・再開はステップ境界で止まる現行方式では
  問題にならない。TypeScript過渡経路にチェックポイント保存・
  復元APIは存在しない（未実装として記録）。

## 半径方向の不連続（独立課題として維持）

板高さの動径ビン不連続（最大約2.9µm）と、法線に滑らかな勾配を
使う混在は、今回の加速度改善とは混ぜない。連続補間を試す場合は
次を独立PRで検証すること:

- 高さとその勾配・時間微分が1つの連続面として整合すること
- 高さ上限・セル範囲などの保守的証明が新しい面でも成立すること
- Python参照と同時に変更し、解析的な固有関数（Bessel形）へ
  近づく方向であることを独立に確認すること
