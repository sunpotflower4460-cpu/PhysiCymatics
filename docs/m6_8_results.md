# M6-8 結果: ライブ自由度マスクと浅い接触の収束研究

比較対象は M6-7 マージ後の main 標準設定。設計は `docs/m6_8_design.md`。
再実行方法:
`PHYSI_BENCH=1 npx vitest run src/simulation/__tests__/bench_m67.test.ts`
（`PHYSI_BENCH_MODES=base,nomask` でマスクの A/B）
収束研究: `PHYSI_BENCH=1 npx vitest run src/simulation/__tests__/study_shallow.test.ts`

注意: 本計測環境はセッション間で絶対速度が 2〜3 倍変動する
（単位コスト実測でも確認）。そのため効果は同一計測内での
A/B 比率で報告する。評価回数・衝突回数などのカウンタは不変。

## 採用したもの: ライブ自由度マスク（M6-8A）

中心駆動では 18 自由度中 m=0 の 2 つだけが励振される。残りの
自由度は Hermite 端点が全て 0 で寄与が厳密な 0 のため、高さ・
加速度評価とその係数キャッシュをライブ自由度だけに限定した。
ビット一致をテストで固定（死んだ自由度を含むケースを含む）。

同一計測内 A/B（マスクなし→あり、順序を入れ替えた2回の計測で整合）:

| 条件 | 短縮率 |
|---|---:|
| 600,000・弱・初期 0.02 s | -19% / -24% |
| 100,000・弱・初期 0.05 s | -41% / -31% |
| 20,000・強・0.2 s | -27% / -31% |
| 5,000・強・0.5 s | -29% / -25% |
| 5,000・弱・形成後 0.5 s | -33% |

偏心駆動など全自由度が生きる条件では効果は消えるが、悪化もしない
（マスク計算はセグメントあたり 18 回の比較のみ）。追加メモリは
自由度数ぶんの整数配列のみ。ベンチ用の無効化スイッチ
（`liveMaskEnabled`）で旧経路に戻せる。

## 浅い接触の収束研究（M6-8C、研究のみ）

時間刻み（spp=44 既定 / 88 / 176）で同じ初期条件を計算し、
衝突・離脱回数を比べた（60 粒・物理 0.15 s・休止なし）:

| 周波数 | spp=44 | spp=88 | spp=176 |
|---|---|---|---|
| 152 Hz | 衝突 731 | 729 | 729 |
| 649 Hz | 衝突 1,288 / 離脱 900 | 1,259 / 858 | 1,260 / 854 |
| 1,241.6 Hz | 衝突 1,800 / 離脱 83 | 1,843 / 92 | 1,472 / 0 |

読み取り:
- 152 Hz では既定刻みでほぼ収束している。
- 649 Hz では既定刻みが細かい刻みより衝突・離脱を数 % 多く数える。
  細かい2条件はほぼ一致する。単純な「見逃しで少なくなる」形ではなく、
  接触時刻のずれが軌道全体へ伝播した結果と見られる。
- 1,241.6 Hz（共鳴）では刻み間で大きく異なり、未収束。
  カウント比較だけでは浅い接触の見逃し分を分離できない。

結論: 高周波では現行の時間解像度自体が結果に数 % 以上影響する。
これは 8 サンプルの見逃しだけでなく、RK4＋Hermite の区間表現と
カオス的増幅を含む複合であり、真の連続衝突検出（包含判定による
根の存在証明）を参照として初めて切り分けられる。既存経路は
変更していない。

## 60 万粒までの距離

初期 0.02 s の単一計算は同一計測内で約 22.6〜26.0 秒（マスクあり、
機械負荷により変動）。物理 1 秒あたり約 1,100〜1,300 秒相当の
セッションもあれば約 550 秒相当のセッションもあり、絶対値は
環境依存が大きい。いずれにせよリアルタイムには約 2 桁以上の差。
支配項は依然として接触解決の高さ評価（接触 1 件あたり
サンプル＋二分探索で約 37 回）である。

## 採用しなかったもの・残課題

- 二分探索回数の削減や接触探索の置換（B系統）: Python 参照との
  一致が変わるため、高精度参照による独立検証の設計が先。未着手。
- 着座粒子の空間キャッシュ: メモリ数十 MB に対し数 % の見込みで見送り。
- GPU: Float64 参照との差分検出の仕組みが先。今回は調査のみ:
  WebGPU は Float64 を標準で持たず、接触時刻の一致保証ができない
  ため標準経路には使えない。
