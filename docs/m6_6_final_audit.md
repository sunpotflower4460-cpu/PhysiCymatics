# M6-6（PR #9）最終監査記録

対象: PR #9 `m6-6-adaptive-slices`（監査時点 HEAD `dfe762a`、
その後計測フックの限定化のみ追加。物理経路への変更なし）
前提: PR #8（M6-5R）は main へマージ済み。本 PR は main へ付け替え済みで、
差分は M6-6 固有の 9 ファイルのみ（#8 の変更の重複なし）。

## 独立監査の結果

- `heightAt`: `surfAt` の高さ項と同一の演算（同じ動径ビン、同じ三角
  漸化、同じ和の順序、同じ Hermite 係数式）であり、ビット一致テスト
  （ランダム点・境界点・板の外側を含む）で固定されている。
- 接触の確定計算（法線・板速度が必要な箇所）は従来どおり `surfAt`
  全量を使っており、必要な物理量は失われていない。高さ専用評価は
  サンプル・二分探索・終端判定など高さだけを比べる箇所のみ。
- キャッシュ無効化: 高さ専用の係数キャッシュは `beginStep` で
  毎ステップ無効化される。スライス範囲キャッシュはセグメント
  オブジェクト同一性で鍵付けされ、周波数・楽譜変更では新しい
  セグメントになるため古い値を参照しない。
- 時間スライス証明は標準で無効（`localSplits` 未指定 = 1 = M6-5 の
  全体証明）。Worker の生成経路もオプションを指定していない。
  有効化しても適用域・失敗時の扱いは M6-5R と同一で、ON/OFF の
  ビット一致がテストで固定されている。
- 追加メモリ: 高さ専用キャッシュは 64×18 の倍精度配列程度。
  スライス用配列は有効化時のみ確保され、k=8 でも 1 MB 未満。
- 性能向上の再現: `docs/m6_6_results.md` の実測（22〜33% 短縮、
  衝突・離脱回数は全条件で一致）。再実行可能なベンチを同梱。

## 監査で見つけて直した点

- ブラウザ計測用に公開していた `window.__physiPool` 参照を、
  開発・計測経路（`?count=` / `?workers=` 指定時）だけに限定した。
  通常利用のビルドでは公開されない。プール自体の計時フィールドは
  読み取り専用の診断情報で、制御には使われていない。

不採用の時間スライスは既定で無効。未解決の重大な指摘はない。
