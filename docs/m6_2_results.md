# M6-2 休止・イベント駆動の実装結果（M6-2R 改訂）

設計の根拠は `docs/m6_2_event_driven_design.md`。本書は実装と実測の記録。
M6-2R では Codex レビュー2件と Hermite 高さ上限の問題に対応し、
休止判定の根拠を「モード ODE のエネルギー上限＋固定余裕」から
「実際の RK4＋Hermite 計算に対する板の先読み範囲」へ置き換えた。

## 実装した休止方式（M6-2R）

- 物理状態（FLYING / SITTING / LOST）と計算管理状態（通常走査 / 休止）を分離。
  休止は新しい物理状態ではなく「その区間は状態変化が起きないと判定できた」
  という管理情報（`sleeping` + `wakeT` + `sleepT0`）。
- 板の先読み: 板は砂から反作用を受けないため、モード状態を複写し、
  本体と同一の公称 dt 列・同一の RK4 で最大 0.5 秒先まで進め、
  各自由度について Hermite 区間内の厳密な範囲を求める
  （加速度 qdd は区間内で線形＝端点、変位 q は3次＝端点＋臨界点）。
  着座休止はこの範囲から `wtt = Σ qdd_j Φ_j` の下限を区間演算で求め、
  `g + wtt >= 0` が休止区間全体で保証できる場合だけ採用する。
  先読みは粒子数に依存せず、複数粒子で共有する（キャッシュ）。
- 先読みの前提は「短縮されない公称 dt 列」。カスタム dt や
  `advanceTo` の最終部分ステップでは全粒子を起こし、そのステップは
  休止を使わず基準経路で処理する。
- 飛行休止: 先読みした各自由度の変位範囲から板高さの安全な上限を求め、
  放物線がその上限より下へ来ない期間だけ休止する。板外到達時刻
  （直線と円の交点）も起床候補。下限到達後は M6-1 の接触探索へ戻る。
- Hermite 高さ上限の係数を 0.105 → 4/27 へ修正
  （接線基底の最大値は s=1/3 で 4/27。0.105 は過小だった）。
- c_roll > 0 のときは着座休止を行わない。着座中も水平移動するため、
  鉛直加速度だけでは「状態変化なし」を保証できないためである。
- 起床はステップ開始時点で行い、飛行粒子の復元は公称 dt の区切りで
  行う。基準経路の積み上げ順序に近づけ、浮動小数点の差を小さくするため。
- イベント回数上限到達時に粒子を強制着座させない。TS・Python とも
  上限後は残り区間を8分割し、接触を確認しながら進める。発生回数は
  数える（今回の全測定条件では 0 回。着座は粘着条件からのみ起こる）。
- 非弾性崩壊の正則化（上限到達とは別の話として明記）: 接触時に粒子を
  板面＋1e-9 m へ置くため、反発の頂点が板面から 1e-8 m 未満の跳ねは
  この接触表現では分解できず、数値的な極限周期になる。そこで粘着
  しきい値に下限 sqrt(2g·9e-9) ≈ 4.2e-4 m/s を置く（頂点 10 nm は
  砂粒の大きさの約1万分の1）。これは回数ではなく分解能の規則であり、
  駆動中の通常の粘着しきい値（0.3×板速スケール）より小さいため、
  通常条件の結果は変えない（fixture の回数は不変で確認）。
- 短すぎる休止（8ステップ以下）は管理コストの方が高いため採用しない。
  休止判定に失敗した粒子は16ステップ再判定を空ける（管理のみの最適化）。
- 周波数・score・駆動点の変更時は全休止を無効化（状態は現在時刻へ復元して保持）。
- 休止あり/なしは切替可能（`sleep_enabled` / `{enabled}`）。基準経路は残してある。

## 休止あり/なしの一致（検証）

- TS・Python の両方で同一初期条件の on/off 比較テストがある。
  短い区間では衝突・離脱回数と残存数が一致し、位置差は許容値内。
- 許容値の根拠: 休止飛行粒子の復元は基準経路と演算順序が異なるため
  起床時に約 1e-12 m の差が生じ、衝突のカオス的増幅で広がる。
  実測では 152Hz・0.6秒で最大 1.8e-6 m、649Hz 帯で最大 4.3e-5 m。
  このため位置の合格線は 152Hz 帯で 5e-6 m、600Hz 以上で 1e-4 m とし、
  主な判定は回数・状態の一致に置く。1秒の強い駆動では回数にも
  約 0.03% の差が出る（下表）。現象の違いではなく数値の分岐である。
- Codex の反例（入力 70Hz、649Hz 付近モードに残留振動、着座粒子が
  休止 ON で離脱を見逃す）を TS・Python 双方に回帰テストとして保存した。
  旧方式では Hermite 加速度が -10.04 m/s² に達するのに ODE 上限は
  9.42 m/s² と言っていた。先読み方式ではこの粒子は休止しない。
- Python/Web 照合（M6 fixture）は休止 OFF 同士で 1e-6 m 未満・回数一致を
  合格線とする（物理そのものの照合）。休止の照合は各言語の on/off
  テストが担う。休止 ON 同士の言語間比較は管理判断の差で演算順序が
  変わるため厳密な合格線には使わない。

## 実測（TS・Node、152Hz、較正力、物理1秒）

| 条件 | 休止なし | 休止あり | 省略した更新 | 衝突/離脱回数（なし→あり） |
|---|---|---|---|---|
| 500粒・力×1.0 | 3,063ms | 3,102ms | 2,053,392 | 19,357→19,357 / 10,947→10,946 |
| 5,000粒・力×1.0 | 30,746ms | 31,882ms | 20,314,017 | 199,825→199,881 / 116,285→116,300 |
| 2,000粒・力×0.05 | 17,960ms | 13,555ms | 7,397,277 | 179,358→179,327 / 59,872→59,874 |

イベント上限到達は全条件 0 回。休止判定の回数は 5,000粒条件で
約 83 万回、起床は約 4 万回。

正直な読み方: 先読みによる保証を強めた代償として、強い駆動では
休止の利益がほぼ消えた（約 ±4%）。弱い駆動では約 25% 短い。
60万粒リアルタイムの保証にはならない。M6-2R の成果は速度ではなく
「保証できない休止をしない」ことの確立である。

## 空間的な計算共有（M6-2E）について

今回は粒子ごとの `Φ_j(x,y)` 評価を休止判定でのみ使い、領域分割による
共有は未実装。理由: 休止判定の正確さをまず粒子単位で固定するため。
領域上限（領域内全粒子に安全な bound）への拡張は M6-3 の候補。

## スマートフォンへの適性

- 粒子状態は連続配列のまま。休止管理も TypedArray 数本のみ追加。
- snapshot は休止飛行粒子の位置を解析式で復元するため転送量は不変。
  （休止粒子を送らない最適化は未実装。）
- GPU不要の経路を維持。

## 未解決の限界

- 休止の保証は「実装した RK4＋Hermite 計算」に対するものであり、
  実物の板の保証ではない。モード打切り（1300Hz超）の物理精度は
  従来どおり未検証。
- 浮動小数点の演算順序の差は残るため、休止 ON/OFF はビット一致しない。
  長時間の強い駆動では回数統計にも小さな差が出る。
- サンプル間で完結する浅い接触の見逃し（M6-1 の床）は休止でも
  増やしていない（下限到達後に通常探索へ戻るため）。完全検出ではない。
- c_roll>0 の着座粒子と、将来の粒子間衝突・摩擦モデルには
  現在の休止条件を無条件に適用できない（c_roll>0 は着座休止を無効化済み）。
- TS と Python でイベント上限の数え方が異なる（TS: 粒子ごと8回、
  Python: 全粒子で512ラウンド）。上限後の区間分割処理は揃えたが、
  上限へ到達する条件では言語間で結果が分岐し得る。測定条件では到達0回。
- Python 参照の休止は照合用であり、速度は依然として遅い。

## M6-3 へ進めるかの判定

進める。休止の安全性は現在のモデル範囲で根拠を持ち、反例は回帰
テスト化された。ただし M6-3 の主眼は速度であり、先読みキャッシュの
共有範囲拡大・全粒子走査の除去（イベントキュー）・領域上限の共有が
必要である。設計は `docs/m6_2_event_driven_design.md` の M6-3 節に記す。
