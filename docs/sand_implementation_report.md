## 検証結果

- **オラクル照合（移植の検証）**: 同じ初期配列・同じ条件で `oracles/c002_sand/c002b.simulate` と最大差 **0.0**（ビット一致、バウンス数・着座も一致）。オラクルは無変更。
- **単体力学**: 自由落下は解析解と一致。静止面（Γ=0）反発は e 以下でエネルギー増なし。表面の `wtt = −ω²w` 一致、符号保持を確認。
- **目標力なし**: `step()` 内に節半径への参照がないことをテストで検査。節円は測定（stats・映像の破線）でのみ使用。
- **Γ=80・24秒**: 中央値|W| 0.415→**0.144**、リング濃縮 **2.96倍**、残存 373/500。c002 既報（0.144 / 約3倍）と整合する計算結果。
- **Γ=0.8 対照**: 中央値|W| 不変（0.415）、trapped=1.0、喪失ゼロ ＝ 凍結。弱く振ると動かない、という計算結果。
- **回帰**: 全体 54 passed（既存47＋新規7）。

## モデルの範囲（正直な床）

今回計算したのは「単一モード・独立粒子」のモデルです。以下はまだ計算していません。

- 粒子同士の衝突・砂山、空気、砂から板への反作用
- 音程変更時の板の過渡応答（M3）、音（M1映像は無音）
- 反発係数などは仮定値。実物の砂との定量一致は未測定
- 映像の破線円は測定用の重ね表示で、粒子の動きには影響しません

## M3 成果物（ブラウザで実際に操作して確認したもの）

| 成果物 | 内容 |
|---|---|
| `reference/plate_transient.py` | 多モード過渡応答の参照実装（モーダル質量・cos/sin両方向・RK4＋Hermite状態評価・砂接続） |
| `webapp/src/simulation/plateTransient.ts` / `transientSand.ts` | TS版（同一アルゴリズム）。モード表は `scripts/gen_transient_web_data.py` 生成（1300Hzまで10モード・18自由度） |
| `webapp/src/simulation/sequence.ts` | score（区間・位相積分・包絡）とPCM生成。力[N]と音量は別単位で同じu(t)を読む |
| `webapp/src/audio/sequenceAudio.ts` | scoreのPCM再生（停止位置保持、物理が遅れたら音を待たせる） |
| Sand表示「演奏・自由周波数」 | 演奏プリセット（152→649→368.6Hz・各12秒）、自由周波数入力（20〜2000Hz・吸着なし）、駆動点切替。どれも板・砂の状態を保持 |

検証:

- **解析照合**（Python/TS両方）: 共鳴から外した駆動での定常振幅が1自由度の解析式と2%以内で一致。自由減衰・中央駆動でm>0が励起されない対称性を確認。
- **連続性**: 周波数切替の前後で q・qd・粒子位置が飛ばないことをテストで確認。scoreの位相は区間境界で連続、PCMのサンプル数・境界時刻が一致。
- **ブラウザ操作**: 演奏再生で振幅尺度が約842µm（較正目標860µm付近）まで立ち上がり、173.3Hz（プリセット外）へ変えると表示・駆動とも173.3Hzのまま振幅が133µmへ低下＝吸着も細工もない計算結果。状態（時刻・残存数）は継続。エラーなし。
- **実測した物理の進み**: 多モード・500粒で約×0.5（開発機ブラウザ）。単一モード500粒は×1.00のまま。
- テスト: Web 15件・Python 60件、すべて緑（過渡テスト追加でPythonは約45秒）。

未検証として残すもの: 保持モードを増やした打切り収束の定量比較、20〜2000Hz全域の精度（入力は通るが全域の精度確認は未実施）、実機スピーカーでの聴感同期（ヘッドレスでは無音確認のみ）。

## M5 実測と到達点（60万粒は未達）

ベンチマーク（`scripts/bench_sand_scale.py`、`renders/scale_benchmark.json`、開発機）:

| 粒子数 | 実測速度（単一モード） |
|---|---|
| 500 | 約106万 粒子step/秒 |
| 2,000 | 約308万 |
| 20,000 | 約1,198万 |
| 100,000 | 約1,064万 |

到達した最大の動画: `renders/m5_scale100k/clip.mp4`（初期100,000個の独立粒子・Γ=80・10秒・540×960・5fps、残存77,149粒、リング濃縮2.74倍、生成に約593秒）。複製や間引きはなし。

60万粒への見積もり（実測からの線形外挿）:

- 単一モード36秒: 約3.4時間（計算のみ。描画・IO別）
- 多モード演奏36秒: 過渡backendの大規模実測は 20,000粒=約26万、100,000粒=約27万、**600,000粒=約34万 粒子step/秒**（152Hz・短時間実測）。36秒score（約61.8万step）では **約301時間（12.5日）**

高速化と再開の実装（実施済み）:

- 表面評価を積み重ね表＋einsumのバッチ処理へ変更し、従来の per-DOF 計算と **1e-12未満で一致**することをテストで確認
- `render_sand_clip.py` にチェックポイント再開（`--ckpt-every` / `--resume`）を追加。中断→再開した結果が一括実行と**最終状態ハッシュ・最終フレームとも一致**することを確認
- 60万粒ジョブを実際に開始: `renders/m5_600k/` にフレーム3枚とチェックポイント（600,000粒・全粒残存）があり、`--resume` で続きを計算できることを証明した

**判断: 60万粒の完成動画は未達のまま記録する。** 実測では約301時間かかるため、このセッションでは完了できない。ジョブはチェックポイントから再開可能で、自分の端末で次を実行すれば続きが進む（中断してもフレーム単位で保存される）:

```bash
.venv/bin/python scripts/render_sand_clip.py --backend transient --seg 12 --np 600000 --fps 30 --width 540 --height 960 --ckpt-every 1 --resume --output renders/m5_600k
```

現実的な完了には GPU/WASM 等の高速backend（数値照合つき）が追加で必要。
