# M6-4 設計: 表面評価の高速化・粒子並列計算・大規模描画

物理モデルと休止保証は M6-2R/M6-3 から変更しない。本書は計算構造の
設計判断を記録する。実測は `docs/m6_4_results.md`。

## 4A 板表面評価（surfAt）の高速化【実装済み】

支配コストの内訳（M6-3R 実測）: 表面評価は粒子ステップあたり約2回、
5,000粒・0.5秒で約3,350万回。旧 surfAt は呼び出しごとに

- Hermite の基底係数（時刻だけの関数）を自由度ごとに再計算
- 三角関数の漸化用に配列を2つ新規確保
- オブジェクト経由のモード参照と `dR/a` の除算を毎回実行

していた。最適化版は

- 時刻係数（自由度ごとの q/qd/qdd）を、同一区間内では正確な時刻を
  キーに共有する（直接マップ方式のキャッシュ、区間ごとに消去）。
  着座判定（区間端の時刻）と飛行の第1ラウンドのサンプル時刻は
  多くの粒子で一致するため共有が効く。二分探索の時刻は共有されず
  従来どおり計算する（キャッシュに入るだけ）。
- 漸化用配列は再利用スクラッチへ、R と dR/a は平坦化した表へ、
  自由度記述は型付き配列へ。

演算式と合計順序は旧実装と同一に保ち、最適化版と参照版
（`surfAtReference` として保持）の出力がビット一致することを
テストで固定した。着座粒子の空間重みの粒子ごとキャッシュは、
メモリ（粒子あたり自由度×3×8B）が大規模で重いため採用しなかった。

## 4B 複数 Worker 並列計算

### 方式の選択

候補1: 各 Worker が板の時間発展を再現する。
候補2: 板状態を一箇所で計算し区間単位で配布する。

板の発展は粒子から反作用を受けず決定的であり、コストも物理1秒
あたり約0.1秒と小さい。候補2は毎ステップ（最大で毎秒6,688回）の
配布通信が必要になる。よって候補1（複製）を採用する。全 Worker が
同じ score・同じステップ列を実行すれば板状態は一致する。

### 分割と同一性

- 初期粒子群は従来どおり (count, seed) から一括生成し、連続区間へ
  分割する。各 Worker は自分の区間のみを保持する（メモリは分割数に
  比例して増えない）。粒子 ID は全体の番号を保持する。
- 物理時刻の同期: 調整役（メインスレッド）が全 Worker へ同じ
  ステップ数のバッチを送り、全員の完了を待ってから表示する。
  周波数・駆動の変更メッセージはバッチの合間に送られるため、
  全 Worker で同じステップ境界に適用される。
- 世代番号: 初期化のたびに世代を進め、古い世代のフレームは捨てる。
  撒き直し後に遅れた結果が新しい状態を上書きすることはない。
- 休止・スケジューラ・領域共有は Worker 内でそのまま働く。
- SharedArrayBuffer は使わない（通常の転送のみ）。
- Worker 数は端末のコア数から決め、上限を設ける。1 の場合は
  従来と等価な単一 Worker 経路になる。

### 検証

- プロセス内で分割を再現し、単一シミュレーションと粒子ごとに
  一致すること（独立粒子のためビット一致を期待）をテストする。
- ブラウザで Worker 数 1/2/4/8 の物理進行速度を測る。

## 4C 大規模描画

- WebGL の点描画（gl.POINTS）を第一候補とし、座標は粒子番号順の
  バッファに置く。差分フレームの変更範囲だけを部分更新し、
  変更が広い場合は全量更新へ切り替える。
- 消失粒子は描画範囲外の座標にして描かない（粒子数の水増しなし）。
- WebGL が使えない・コンテキスト喪失時は Canvas 2D へ戻す。
- 描画単体ベンチ（物理停止・既知座標）と統合ベンチを分けて測る。

## 4D 統合検証

構成ごとに ON/OFF できる形を保ち（surfAt 参照版、Worker 数、
描画バックエンド）、M6-3R と同一初期状態で衝突・離脱・休止・
消失・位置を比較する。性能は反復・順序回転・中央値で測る。
