# M6-2 イベント駆動設計（M6-1E 成果物）

目的: 物理的に状態変化が起きない区間を、安全に判定できた場合だけ飛ばす。
模様を指定する仕組みではない。節への吸引・位置補正は一切入れない。

## 状態の定義（現在の独立粒子モデル）

| 状態 | 定義 | 位置の復元方法 |
|---|---|---|
| SITTING（接触静止） | 板上にあり `g + wtt(x,y,t) >= 0` が保たれる。c_roll=0 では水平力なし | `z = h(x,y,t)`、x/y は着座時の値 |
| FLYING（飛行） | 重力のみ。接触まで解析式で位置が決まる | 放物線 `z0+vz0 τ-gτ²/2` 等 |
| LOST（板外） | `r > a`。以後計算しない | — |

## 状態が切り替わる物理条件（イベント）

| イベント | 条件 | 処理 |
|---|---|---|
| CONTACT | 飛行中の gap `z_ballistic - h` が最初に 0 へ達する | 法線反発 e・接線 β で速度更新 |
| STICK | 衝突後の法線速度 `|vn2| < 0.3*v_scale` | SITTING へ |
| DETACH | `wtt(x,y,t) < -g`（支持力 N<0） | その時刻から飛行。vz = 板面速度 |
| EDGE_LOSS | `r > a` | LOST へ |
| INPUT_CHANGE | 周波数・駆動力・駆動点の変更 | 全ての検査予定を無効化 |

## 計算を省略できる条件

### SITTING の休止

区間 `[t, t+T]` で次がすべて確認できれば、その粒子のステップ更新を省略できる。

1. `g + wtt(x,y,τ) >= 0` が全区間で成立する。
2. 水平移動の力がない（現モデル c_roll=0、粒子間衝突なし）。
3. 区間内に INPUT_CHANGE がない。

検証方法: Hermite 区間内では固定 (x,y) に対する wtt は時刻の一次関数。
したがって1ステップ内では両端の値だけで判定できる（M6-1で実装済み）。
複数ステップへ広げるには、モード応答の包絡で上限を bound する:
`|wtt(x,y,τ)| <= sum_j |qdd包絡_j| * |Phi_j(x,y)|`。
定常駆動では q の振幅包絡が有界なので、「今後も g+wtt>=0 が保証できる」
粒子（例: 振幅の小さい位置にいる粒子）は、駆動が変わるまで休止できる。
保証できない粒子は、次に `wtt = -g` へ到達し得る最も早い時刻を
次回検査時刻として登録する。

### FLYING の休止

次の接触時刻の「安全な下限」が求まれば、その時刻まで更新を省略できる。
下限の例: 板面高さの上限 `h_max(t区間) <= sum_j |q包絡_j| |Phi_j|` を使い、
放物線がその上限へ達する時刻を解く。実際の接触はその後なので安全側。
下限時刻が来たら通常の first-contact 探索へ戻る。

## 省略できない条件

- `g + wtt >= 0` を保証できない SITTING 粒子。
- 接触下限時刻を過ぎた FLYING 粒子。
- c_roll>0（転がり）や粒子間衝突を入れた将来モデルでの SITTING 全般。
  その場合は「近傍粒子からの再起動」を別途設計するまで休止を使わない。
- 駆動変更直後（包絡が変わるため全予定を破棄）。

「速度が小さいから寝かせる」等の経験的判定は採用しない。

## 検査予定を無効化する条件

- 周波数・駆動力・駆動点・score の変更（INPUT_CHANGE）。
- 一時停止は無効化しない（物理時刻が止まるだけ）。
- 粒子間衝突を導入した場合は、衝突した粒子の近傍も無効化対象になる。

## 必要なデータ構造

- 粒子ごと: 状態、次回検査時刻 `next_check_t`、着座位置または飛行の初期値。
- 時刻順の予定を取り出すための優先度付きキュー（最小ヒープ）または
  時間バケット。Web では Float64Array + バケットが軽い。
- 空間分割（任意）: 領域ごとに `max|Phi|` 系の上限を事前計算し、
  領域単位で休止可否を先に判定する。節の位置情報は使わない
  （使うのは振幅・加速度の上限という物理量だけ）。

## Python・Web への実装方法（M6-2）

1. まず SITTING 休止だけを入れる（効果が大きく、条件が厳密）。
   休止粒子は描画時に `z=h(x,y,t)` で復元し、snapshot は従来どおり作る。
2. 次に FLYING の接触下限による省略を入れる。
3. どちらも「省略なし」経路と常時比較できるフラグを残す。

## 数値検証方法

- 休止あり/なしで同一初期状態を走らせ、位置・速度・衝突回数・離脱時刻が
  許容誤差内（位置 1e-6 m を初期案）で一致することを確認する。
- 休止判定の偽陰性（本当は離脱するのに休止）がゼロであることを、
  ランダム条件の大量ケースで確認する。
- 駆動変更直後の再検査漏れがないことを、変更前後比較で確認する。

## 期待される高速化と限界

- 形成が進むほど SITTING 比率が上がる条件では、大幅な削減が見込める
  （M6-1D の実測で着座割合と処理内訳を確認する）。
- 全粒子が激しく跳ねる条件では効果は小さい。
- 板のモード時間発展そのものは粒子数に無関係で残る。
- 60万粒リアルタイムの保証にはならない。あくまで「不要な計算をしない」
  ための一段階であり、実測で効果を確認してから次へ進む。
