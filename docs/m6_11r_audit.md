## §1 500Hz「51回」の真因（重大）

- 純粋な `step()` 繰り返しでは離脱0回（両方式）。板単独の稠密
  走査（動径400点×2,200区間）でも、真の `wtt < -g` 交差は0.1秒
  間に存在しない。
- `advanceTo(0.1)` は公称刻み2,200回で「ほぼ」0.1に到達するが、
  浮動小数の累積で約1e-15秒届かず、その長さの最終区間を生成
  していた。Hermite加速度は 1/h² を含むため、この区間では
  相殺ノイズ（実測最小 −716,930 m/s²）となり、着座粒子が
  一斉に「離脱」していた。
- 件数が駆動方法に依存する: `advanceTo(0.1)`: 51回、整列
  チャンク: 88回、stepループ: 0回。ODE方式で消えたのは、
  ODE加速度に 1/h² が無いため（物理的優位ではない）。
- 影響範囲: 本番 Web Worker は `step()` のみ→再生への影響なし。
  ただし M6-9/9R/10 の一部研究実験は `advanceTo` 経由であり、
  M6-9R の「呼び出し分割で軌道が変わる」観測の一部は本バグの
  混入と考えられる（修正後に主要結論 D1 を再実行し維持を確認）。

### 修正（TS・Python 共通）

1. `advanceTo`/`advance_to`: 残りが `max(1e-12, dt*1e-9)` 未満
   なら時間だけを進めて区間を生成しない（正準 step 列を維持）。
2. `h < 1e-7` の区間では加速度・係数を必ず安定形（1/h² を
   使わない形）で評価する。公称区間（1e-5〜1e-4秒級）は対象外
   のため本番結果はビット不変。
3. 回帰テスト: TS `accelMode.test.ts` の degenerate tiny step、
   Python `test_advance_to_grid_target_no_degenerate_step`。

修正後: 500Hz 離脱は両方式・spp44/88/176・複数シードで0回。
S1 比較表は f=500 行のみ 51/0→0/0 に変わり、他は不変。

## §2 離脱探索: 区間支援方式への置換

`firstDetachBelow(x,y,ta,tb)`（TS `TransientPlate`／Python 同名）:

- 高速経路: K=8 走査で符号変化→二分探索（旧方式と同一の根）。
- 保証経路: 走査で見つからなければ、Hermite係数の厳密な
  極値から得る加速度下限 `wttLowerBound` で小区間を再帰的に
  篩い、「この小区間には根が存在しない」を区間演算で証明する
  （上限予算48回・深さ10。予算尽きは「不明」として null を
  返す＝不完全性の明示）。
- 対抗実験 R3（`study_m611r.test.ts`、弱駆動で閾値擦過を探索、
  4000点稠密参照）: 旧走査の見逃しは探索範囲で0件（最短の
  閾値下エピソード 0.84µs でも走査点に跨った）。区間方式は
  稠密参照と全件一致・時刻不一致0件。
- 残る限界: 予算尽き時の未発見は否定できない（明示済み）。
  「見逃しが起きない」とは主張しない。旧方式より強いのは、
  篩い落とした小区間については数学的証明がある点のみ。
